# Спливаючий шар коду підтвердження

Спливаюче вікно коду підтвердження на основі графічного клацання.

- У поєднанні з BoxX для реалізації взаємодії зі спливаючими вікнами та підтримки ESC/закриття
- Натисніть ціль на фоновому зображенні
- Підтримує поетапне скасування клацання та механізм автоматичного повтору
- використовувати
  * Загальнодоступна мережа:`https://captcha.webc.pub`
  * Приватне розгортання: [captcha_srv](https://crates.io/crates/captcha_srv)

## Використовуйте демо

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // Після перевірки надішліть маркер до серверної частини
  console.log("Перевірка пройшла маркер:", маркер);
}
```

## повертається значення

Виклик функції повертає `Promise<string | undefined>`:
- **Перевірку пройдено**: повертає код перевірки Base64URL (без заповнення) рядок маркера коду підтвердження.
- **Закрити або скасувати**: повернутися до `undefined`.

## Процес перевірки та бек-енд списання

1. **Перевірка тригера**: зовнішні виклики `Captcha()`.
2. **Отримати діаграму**: `Captcha.js` Ініціювати `GET /` до `captcha_srv`, щоб отримати зображення та ідентифікатор.
3. **Перевірка координат**: після того, як користувач завершить клацання, `Captcha.js` ініціює `POST /` до `captcha_srv` для перевірки координат. Якщо перевірка пройшла успішно, буде повернено маркер у кодуванні Base64URL.
4. **Внутрішня перевірка**: інтерфейс надсилає токен у серверну частину веб-сайту, а серверна частина викликає `captcha_srv` і `GET /verify/{token}`, щоб перевірити та одразу знищити токен.

### Внутрішні інструкції зі списання

Після того, як серверна частина веб-сайту отримає `token`, надісланий інтерфейсом, вона має ініціювати запит до служби `captcha_srv`:

- **Інтерфейс запиту**:`GET /verify/{token}`
- **Параметр шляху**: `token` (рядок Base64URL повертається зовнішнім інтерфейсом)
- **Повернути результат**: `1` означає, що перевірка пройдена та дійсна (буде автоматично знищено); `0` означає недійсний або списаний.
