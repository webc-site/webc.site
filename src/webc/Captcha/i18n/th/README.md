# เลเยอร์ป๊อปอัปรหัสยืนยัน

หน้าต่างป๊อปอัปรหัสยืนยันตามการคลิกกราฟิก

- รวมกับ BoxX เพื่อใช้การโต้ตอบของหน้าต่างป๊อปอัปและการสนับสนุน ESC / ปิด
- คลิกเป้าหมายตามภาพพื้นหลัง
- รองรับขั้นตอนการคลิกเลิกทำและกลไกการลองใหม่อัตโนมัติ
- ใช้
  * เครือข่ายสาธารณะ:`https://captcha.webc.pub`
  * การใช้งานส่วนตัว: [captcha_srv](https://crates.io/crates/captcha_srv)

## ใช้การสาธิต

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // หลังจากยืนยันแล้ว ให้ส่งโทเค็นไปที่แบ็กเอนด์
  console.log("การยืนยันผ่านโทเค็น:", โทเค็น);
}
```

## ส่งกลับค่า

การเรียกใช้ฟังก์ชันส่งคืน `Promise<string | undefined>`:
- **ผ่านการยืนยัน**: ส่งกลับสตริงโทเค็นรหัสยืนยัน Base64URL ที่เข้ารหัส (ไม่มีการเติม)
- **ปิดหรือยกเลิก**: กลับไปที่ `undefined`

## กระบวนการตรวจสอบและการตัดค่าใช้จ่ายส่วนหลัง

1. **การตรวจสอบทริกเกอร์**: การเรียกส่วนหน้า `Captcha()`
2. **รับแผนภูมิ**: `Captcha.js` เริ่มต้น `GET /` ไปที่ `captcha_srv` เพื่อรับรูปภาพและ ID ที่คลิก
3. **การตรวจสอบพิกัด**: หลังจากที่ผู้ใช้คลิกเสร็จแล้ว `Captcha.js` เริ่มต้น `POST /` ไปที่ `captcha_srv` เพื่อตรวจสอบพิกัด หากการยืนยันสำเร็จ โทเค็นที่เข้ารหัส Base64URL จะถูกส่งกลับ
4. **การตรวจสอบแบ็คเอนด์**: ส่วนหน้าส่งโทเค็นไปยังแบ็กเอนด์ของเว็บไซต์ และแบ็กเอนด์เรียก `captcha_srv` และ `GET /verify/{token}` เพื่อตรวจสอบและทำลายโทเค็นทันที

### คำแนะนำในการตัดจ่ายส่วนหลัง

หลังจากที่แบ็กเอนด์ของเว็บไซต์ได้รับ `token` ที่ส่งโดยส่วนหน้าแล้ว จะต้องเริ่มต้นคำขอไปยังบริการ `captcha_srv`:

- **ขออินเทอร์เฟซ**:`GET /verify/{token}`
- **พารามิเตอร์เส้นทาง**: `token` (สตริง Base64URL ที่ส่งคืนโดยส่วนหน้า)
- **ผลลัพธ์การส่งคืน**: `1` หมายถึงการตรวจสอบผ่านและถูกต้อง (จะถูกทำลายโดยอัตโนมัติ) `0` หมายถึงไม่ถูกต้องหรือถูกตัดออกไปแล้ว
