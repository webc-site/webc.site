# الطبقة المنبثقة لرمز التحقق

نافذة منبثقة لرمز التحقق بناءً على النقر على الرسم.

- مدمج مع BoxX لتنفيذ تفاعل النافذة المنبثقة ودعم ESC/الوثيق
- انقر فوق الهدف بناءً على صورة الخلفية
- يدعم خطوة النقر على التراجع وآلية إعادة المحاولة التلقائية
- يستخدم
  * الشبكة العامة:`https://captcha.webc.pub`
  * النشر الخاص: [captcha_srv](https://crates.io/crates/captcha_srv)

## استخدم العرض التوضيحي

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // بعد التحقق، أرسل الرمز المميز إلى الواجهة الخلفية
  console.log("الرمز المميز الذي تم التحقق منه:"، token);
}
```

## قيمة الإرجاع

يؤدي استدعاء الدالة إلى إرجاع `Promise<string | undefined>`:
- ** تم اجتياز التحقق **: إرجاع سلسلة الرمز المميز لرمز التحقق المشفر Base64URL (بدون الحشو).
- **إغلاق أو إلغاء**: العودة إلى `undefined`.

## عملية التحقق والشطب الخلفي

1. **التحقق من صحة الزناد**: مكالمات الواجهة الأمامية `Captcha()`.
2. **الحصول على المخطط**: `Captcha.js` ابدأ `GET /` إلى `captcha_srv` للحصول على الصورة والمعرف الذي تم النقر عليه.
3. **التحقق من الإحداثيات**: بعد أن يكمل المستخدم النقر، يبدأ `Captcha.js` `POST /` إلى `captcha_srv` للتحقق من الإحداثيات. إذا نجح التحقق، فسيتم إرجاع الرمز المميز المشفر Base64URL.
4. **التحقق من الواجهة الخلفية**: ترسل الواجهة الأمامية الرمز المميز إلى الواجهة الخلفية لموقع الويب، وتستدعي الواجهة الخلفية `captcha_srv` و`GET /verify/{token}` للتحقق من الرمز المميز وتدميره مرة واحدة.

### تعليمات الشطب الخلفية

بعد أن تتلقى الواجهة الخلفية لموقع الويب `token` المقدمة من الواجهة الأمامية، فإنها تحتاج إلى بدء طلب إلى خدمة `captcha_srv`:

- **واجهة الطلب**:`GET /verify/{token}`
- **معلمة المسار**: `token` (سلسلة Base64URL التي يتم إرجاعها بواسطة الواجهة الأمامية)
- **نتيجة الإرجاع**: `1` تعني أن التحقق قد تم اجتيازه وصلاحيته (سيتم إتلافه تلقائيًا)؛ `0` يعني أنه غير صالح أو تم شطبه.
