# Усплывальны пласт праверачнага кода

Усплывальнае акно кода пацверджання на аснове графічнага націску.

- У спалучэнні з BoxX для рэалізацыі ўзаемадзеяння з усплываючымі вокнамі і падтрымкі ESC/закрыцця
- Пстрыкніце мэта на аснове фонавага малюнка
- Падтрымлівае механізм адмены пакрокавага націску і аўтаматычны паўтор
- выкарыстоўваць
  * Грамадская сетка:`https://captcha.webc.pub`
  * Прыватнае разгортванне: [captcha_srv](https://crates.io/crates/captcha_srv)

## Выкарыстоўвайце дэма

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // Пасля праверкі адпраўце токен у бэкэнд
  console.log("Праверка прайшла Маркер:", маркер);
}
```

## вяртаецца значэнне

Выклік функцыі вяртае `Promise<string | undefined>`:
- **Праверка пройдзена**: вяртае код праверкі з кодам праверкі Base64URL (без запаўнення).
- **Закрыць або адмяніць**: Вярнуцца да `undefined`.

## Працэс праверкі і бэк-энд спісанне

1. **Праверка трыгера**: інтэрфейс выклікае `Captcha()`.
2. **Атрымаць дыяграму**: `Captcha.js` Ініцыяваць `GET /` да `captcha_srv`, каб атрымаць націснутую выяву і ідэнтыфікатар.
3. **Праверка каардынатаў**: пасля таго, як карыстальнік націсне, `Captcha.js` ініцыюе `POST /` да `captcha_srv` для праверкі каардынатаў. Калі праверка прайшла паспяхова, будзе вернуты токен у кадзіроўцы Base64URL.
4. **Бэкэнд праверкі**: інтэрфейс адпраўляе токен на сервер вэб-сайта, а сервер выклікае `captcha_srv` і `GET /verify/{token}`, каб праверыць і адразу знішчыць токен.

### Бэк-энд спісання інструкцыі

Пасля таго як бэкэнд вэб-сайта атрымае `token`, адпраўлены інтэрфейсам, ён павінен ініцыяваць запыт да службы `captcha_srv`:

- **Інтэрфейс запытаў**:`GET /verify/{token}`
- **Параметр шляху**: `token` (радок Base64URL, які вяртаецца інтэрфейсам)
- **Вярнуты вынік**: `1` азначае, што праверка пройдзена і сапраўдная (будзе аўтаматычна знішчана); `0` азначае несапраўдны або спісаны.
