# שכבת קופץ של קוד אימות

חלון קופץ של קוד אימות המבוסס על קליק גרפי.

- בשילוב עם BoxX ליישם אינטראקציה של חלונות קופצים ותמיכה ב-ESC/סגירה
- לחץ על יעד המבוסס על תמונת רקע
- תומך במנגנון ביטול לחיצה שלב ומנגנון ניסיון חוזר אוטומטי
- לְהִשְׁתַמֵשׁ
  * רשת ציבורית:`https://captcha.webc.pub`
  * פריסה פרטית: [captcha_srv](https://crates.io/crates/captcha_srv)

## השתמש בהדגמה

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // לאחר האימות, שלח את האסימון ל-backend
  console.log("אימות עבר Token:", token);
}
```

## ערך החזרה

קריאה לפונקציה מחזירה `Promise<string | undefined>`:
- **האימות עבר**: מחזירה את מחרוזת קוד האימות Token מקודדת Base64URL (ללא ריפוד).
- **סגור או בטל**: חזור אל `undefined`.

## תהליך אימות ומחיקת קצה אחורי

1. **אימות טריגר**: שיחות קצה `Captcha()`.
2. **קבל תרשים**: `Captcha.js` הפעל את `GET /` אל `captcha_srv` כדי לקבל תמונה ומזהה שלוחצים.
3. **אימות קואורדינטות**: לאחר שהמשתמש משלים את הקליק, `Captcha.js` יוזם `POST /` אל `captcha_srv` כדי לאמת את הקואורדינטות. אם האימות יצליח, יוחזר אסימון מקודד Base64URL.
4. **אימות אחורי**: הקצה הקדמי שולח את האסימון לקצה העורפי של האתר, והקצה האחורי קורא ל`captcha_srv` ו`GET /verify/{token}` כדי לאמת ולהשמיד את האסימון בבת אחת.

### הוראות מחיקה מאחור

לאחר שהקצה האחורי של האתר מקבל את ה`token` שנשלח על ידי הקצה הקדמי, עליו ליזום בקשה לשירות `captcha_srv`:

- **ממשק בקשה**:`GET /verify/{token}`
- **פרמטר נתיב**: `token` (מחרוזת Base64URL המוחזרת על ידי הקצה הקדמי)
- **תוצאת החזרה**: `1` פירושה שהאימות עבר ותקף (יושמד אוטומטית); `0` פירושו לא חוקי או נמחק.
