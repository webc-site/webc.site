# 確認コードポップアップレイヤー

グラフィックのクリックに基づく確認コードのポップアップ ウィンドウ。

- BoxX と組み合わせて、ポップアップ ウィンドウのインタラクションと ESC/閉じるサポートを実装します。
- 背景画像に基づいてターゲットをクリックします
- ステップクリックによる元に戻す機能と自動再試行メカニズムをサポート
- 使用
  * パブリック ネットワーク:`https://captcha.webc.pub`
  * プライベート展開: [captcha_srv](https://crates.io/crates/captcha_srv)

## デモを使用する

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // 検証後、トークンをバックエンドに送信します
  console.log("検証に合格したトークン:", token);
}
```

## 戻り値

関数を呼び出すと、 `Promise<string | undefined>` が返されます。
- **検証に合格**: Base64URL でエンコードされた (パディングなし) 検証コード トークン文字列を返します。
- **閉じるかキャンセル**: `undefined` に戻ります。

## 検証プロセスとバックエンドの償却

1. **トリガー検証**: フロントエンドは `Captcha()` を呼び出します。
2. **チャートの取得**: `Captcha.js` クリックされた画像と ID を取得するために `GET /` から `captcha_srv` を開始します。
3. **座標の検証**: ユーザーがクリックを完了すると、 `Captcha.js` は `POST /` から `captcha_srv` を開始して座標を検証します。検証が成功すると、Base64URL でエンコードされたトークンが返されます。
4. **バックエンド検証**: フロントエンドはトークンを Web サイトのバックエンドに送信し、バックエンドは `captcha_srv` と `GET /verify/{token}` を呼び出してトークンの検証と破棄を一度に行います。

### バックエンドの償却命令

ウェブサイトのバックエンドは、フロントエンドによって送信された `token` を受信した後、`captcha_srv` サービスへのリクエストを開始する必要があります。

- **リクエスト インターフェース**:`GET /verify/{token}`
- **パス パラメーター**: `token` (フロントエンドによって返される Base64URL 文字列)
- **戻り結果**: `1` 検証が合格し有効であることを意味します (自動的に破棄されます)。 `0` は無効であるか、取り消されたことを意味します。
