# ຊັ້ນຂໍ້ມູນປັອບອັບລະຫັດຢືນຢັນ

ໜ້າຈໍປັອບອັບລະຫັດຢືນຢັນໂດຍອີງໃສ່ການຄລິກກາຟິກ.

- ສົມທົບກັບ BoxX ເພື່ອປະຕິບັດການໂຕ້ຕອບຂອງປ່ອງຢ້ຽມປ໊ອບອັບແລະການສະຫນັບສະຫນູນ ESC / ໃກ້ຊິດ
- ຄລິກເປົ້າໝາຍໂດຍອີງໃສ່ຮູບພື້ນຫຼັງ
- ສະຫນັບສະຫນູນຂັ້ນຕອນການຄລິກຍົກເລີກແລະກົນໄກການພະຍາຍາມໃຫມ່ອັດຕະໂນມັດ
- ໃຊ້
  * ເຄືອຂ່າຍສາທາລະນະ:`https://captcha.webc.pub`
  * ການ​ນໍາ​ໃຊ້​ເອ​ກະ​ຊົນ​: [captcha_srv​](/0​)

## ໃຊ້ຕົວຢ່າງ

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // ຫຼັງຈາກການກວດສອບ, ສົ່ງ token ກັບ backend
  console.log("ການຢືນຢັນຜ່ານ Token:", token);
}
```

## ກັບຄືນມູນຄ່າ

ການເອີ້ນຟັງຊັນກັບຄືນມາ `Promise<string | undefined>`:
- **ການ​ຢັ້ງ​ຢືນ​ຜ່ານ​ໄປ**​: ສົ່ງ​ຄືນ Base64URL ເຂົ້າ​ລະ​ຫັດ​ການ​ກວດ​ສອບ (ບໍ່​ມີ padding​) ລະ​ຫັດ Token string​.
- **ປິດ ຫຼື ຍົກເລີກ**: ກັບໄປທີ່ `undefined`.

## ຂັ້ນຕອນການຢັ້ງຢືນ ແລະການຂຽນຄືນຫຼັງ

1. **ການກວດສອບຕົວກະຕຸ້ນ**: ການໂທ Frontend `Captcha()`.
2. **ຂໍຕາຕະລາງ**: `Captcha.js`ລິເລີ່ມ `GET /`ເພື່ອ `captcha_srv`ເພື່ອເອົາຮູບທີ່ຄລິກ ແລະ ID.
3. **ການ​ຢືນ​ຢັນ​ການ​ປະ​ສານ​ງານ**​: ຫຼັງ​ຈາກ​ທີ່​ຜູ້​ໃຊ້​ສໍາ​ເລັດ​ການ​ຄລິກ​ໃສ່​, `Captcha.js`​ລິ​ເລີ່ມ `POST /`​ເພື່ອ `captcha_srv`​ເພື່ອ​ກວດ​ສອບ​ພິ​ກັດ​. ຖ້າການກວດສອບປະສົບຜົນສໍາເລັດ, Base64URL encoded Token ຈະຖືກສົ່ງຄືນ.
4. **Back-end verification**: Front-end ສົ່ງ Token ໄປຫາ backend ເວັບໄຊທ໌, ແລະ backend ໂທຫາ `captcha_srv` ແລະ `GET /verify/{token}` ເພື່ອກວດສອບ ແລະທໍາລາຍ Token ທັນທີ.

### ຄໍາແນະນໍາການຂຽນຄືນຫລັງ

ຫຼັງ​ຈາກ backend ເວັບ​ໄຊ​ທ​໌​ໄດ້​ຮັບ `token` ສົ່ງ​ໂດຍ front-end, ມັນ​ຈໍາ​ເປັນ​ຕ້ອງ​ໄດ້​ເລີ່ມ​ຕົ້ນ​ການ​ຮ້ອງ​ຂໍ​ກັບ​ການ​ບໍ​ລິ​ການ `captcha_srv`:

- ** ການໂຕ້ຕອບການຮ້ອງຂໍ **:`GET /verify/{token}`
- **ພາຣາມິເຕີຂອງເສັ້ນທາງ**: `token` (ສະຕຣິງ Base64URL ທີ່ສົ່ງຄືນໂດຍດ້ານໜ້າ)
- **ຜົນຕອບແທນ**: `1` ໝາຍເຖິງການຢັ້ງຢືນຜ່ານ ແລະຖືກຕ້ອງ (ຈະຖືກທຳລາຍໂດຍອັດຕະໂນມັດ); `0` ໝາຍ ຄວາມວ່າບໍ່ຖືກຕ້ອງ ຫຼືຖືກຕັດອອກ.
