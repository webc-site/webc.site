# დამადასტურებელი კოდის ამომხტარი ფენა

დამადასტურებელი კოდის ამომხტარი ფანჯარა გრაფიკული დაწკაპუნების საფუძველზე.

- BoxX-თან კომბინირებულია ამომხტარი ფანჯრის ურთიერთქმედების და ESC/დახურვის მხარდაჭერა
- დააწკაპუნეთ სამიზნე ფონის სურათის მიხედვით
- მხარს უჭერს ნაბიჯის დაწკაპუნების გაუქმებას და ავტომატური განმეორებითი ცდის მექანიზმს
- გამოყენება
  * საჯარო ქსელი:`https://captcha.webc.pub`
  * პირადი განლაგება: [captcha_srv](https://crates.io/crates/captcha_srv)

## გამოიყენეთ დემო ვერსია

```js
import Captcha from "webc.site/Captcha.js";

const token = await Captcha();
if (token) {
  // გადამოწმების შემდეგ, გაგზავნეთ ჟეტონი ბექენდში
  console.log("Verification passed Token:", token);
}
```

## დაბრუნების ღირებულება

ფუნქციის გამოძახება აბრუნებს `Promise<string | undefined>`:
- **ვერიფიკაცია გავიდა**: აბრუნებს Base64URL კოდირებულ (შეფუთვის გარეშე) დამადასტურებელი კოდის სიმბოლოს სტრიქონს.
- **დახურვა ან გაუქმება**: დაბრუნება `undefined`-ზე.

## გადამოწმების პროცესი და უკან დაბრუნების ჩამოწერა

1. **ტრიგერის ვალიდაცია**: Frontend ზარები `Captcha()`.
2. **მიიღეთ დიაგრამა**: `Captcha.js` წამოიწყეთ `GET /` `captcha_srv`, რომ მიიღოთ დაწკაპუნებული სურათი და ID.
3. **კოორდინატის დადასტურება**: მას შემდეგ, რაც მომხმარებელი დაასრულებს დაწკაპუნებას, `Captcha.js` იწყებს `POST /`-ს `captcha_srv` კოორდინატების დასადასტურებლად. თუ დადასტურება წარმატებულია, Base64URL კოდირებული ჟეტონი დაბრუნდება.
4. **Back-end ვერიფიკაცია**: Front-end წარუდგენს Token-ს ვებსაიტის ბექენდს, და backend-ი უწოდებს `captcha_srv` და `GET /verify/{token}`, რათა შეამოწმოს და გაანადგუროს ტოკენი ერთდროულად.

### უკანა ბოლოს ჩამოწერის ინსტრუქციები

მას შემდეგ, რაც ვებ-გვერდი მიიღებს `token` წარდგენილ ფრონტ-ენდის მიერ, მან უნდა დაიწყოს მოთხოვნა `captcha_srv` სერვისზე:

- **მოითხოვეთ ინტერფეისი**:`GET /verify/{token}`
- **გზა პარამეტრი**: `token` (Base64URL სტრიქონი დაბრუნდა წინა ბოლოდან)
- **დაბრუნების შედეგი**: `1` ნიშნავს, რომ ვერიფიკაცია გავიდა და მოქმედებს (ავტომატურად განადგურდება); `0` ნიშნავს არასწორი ან ჩამოწერილია.
